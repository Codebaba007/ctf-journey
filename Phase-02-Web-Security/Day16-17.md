## What I Learned

### Web Application Security

A web application is software that users interact with through a web browser. The browser communicates with a remote server using HTTP or HTTPS.

Understanding the requests sent by the browser and the responses returned by the server is important when assessing web application security.

### Identification and Authentication

**Identification** is the ability to identify a user uniquely.

**Authentication** verifies that the user is actually who they claim to be.

Common authentication weaknesses include:

- Brute-force attacks
- Weak passwords
- Poor credential handling
- Unlimited login attempts

### Broken Access Control

Access control determines what resources and functionality a user is allowed to access.

Users should only be able to access resources appropriate for their role and permissions.

A common principle is **least privilege**, where users receive only the permissions they actually need.

Examples of broken access control include:

- Accessing another user's information
- Modifying another user's resources
- Accessing authenticated functionality without authentication
- Accessing functionality intended for higher-privileged users

### Injection

Injection vulnerabilities occur when an application accepts user-controlled input and processes it as code or commands without proper validation and sanitization.

The key idea is that untrusted input should not be interpreted as executable instructions.

### Cryptographic Failures

Sensitive information should not be exposed through insecure transmission or weak cryptography.

Examples include:

- Sending sensitive information in cleartext
- Using weak cryptographic algorithms
- Using weak or default cryptographic keys
- Poor protection of sensitive data

### IDOR

**IDOR** stands for **Insecure Direct Object Reference**.

It is a type of **Broken Access Control** vulnerability.

An application may expose a direct reference to an object, such as an ID:

    /profile?id=100

If changing the identifier allows a user to access another user's resource without the server properly checking authorization, the application may be vulnerable to IDOR.

The important issue is not simply that an ID can be changed.

The real problem is that the server fails to verify whether the authenticated user is authorized to access the referenced object.

### Horizontal Privilege Escalation

Horizontal privilege escalation occurs when a user accesses another user's resources while remaining at the same privilege level.

Example:

    User A → User B's profile

### Vertical Privilege Escalation

Vertical privilege escalation occurs when a lower-privileged user gains access to functionality belonging to a higher-privileged user.

Example:

    Normal User → Administrator functionality

## Practical Experience

The practical section involved an Inventory Management System.

I explored the application's functionality and investigated how resources were referenced.

The application contained an IDOR vulnerability where object references could be manipulated.

This demonstrated how changing a user-controlled identifier can potentially expose or modify another user's resources when proper server-side authorization checks are missing.

## Authentication vs Authorization

A key distinction from this room:

**Authentication**

    Who are you?

**Authorization**

    What are you allowed to access or do?

Successfully authenticating as a user does not mean that the user should automatically have access to every resource.

## Important Security Mental Model

When testing an application, do not only ask whether a parameter can be changed.

Instead ask:

    What does this parameter control?
            ↓
    What resource does it reference?
            ↓
    Who should be allowed to access that resource?
            ↓
    Does the server verify authorization?
            ↓
    What happens if the value is changed?

Security decisions should be enforced by the server rather than relying only on client-side restrictions.

## Key Takeaways

- Identification identifies a user.
- Authentication verifies a user's identity.
- Authorization determines what a user is allowed to do.
- Broken Access Control can allow unauthorized access to resources or functionality.
- Least privilege limits users to the permissions they actually require.
- IDOR is a Broken Access Control vulnerability.
- User-controlled object references must be properly authorized by the server.
- Horizontal privilege escalation involves accessing another user's resources.
- Vertical privilege escalation involves gaining higher-level privileges.
- Injection occurs when untrusted input is improperly interpreted as code or commands.
- Cryptographic failures can expose sensitive information through cleartext transmission or weak cryptography.
- Client-side restrictions should not be treated as a reliable security boundary.
- Understanding normal application behavior is important before identifying security weaknesses.
