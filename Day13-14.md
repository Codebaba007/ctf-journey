## What I Learned

### Why Organizations Need Security Engineers

Modern organizations depend heavily on digital systems, networks, applications, cloud infrastructure, and data. This creates security risks that cannot simply be solved by using technology without considering security. A security engineer helps protect the organization's digital assets while allowing the organization to continue achieving its business objectives.

A security engineer may be responsible for minimizing cybersecurity risk, designing security strategies, implementing secure network solutions, engineering trustworthy systems, testing security controls, identifying weaknesses, and coordinating security requirements across teams. The role is broad because security problems are broad and constantly changing.

### Security Engineer Mindset

A security engineer is not simply someone who attacks systems. The role involves engineering security into systems and organizations. A security engineer needs to understand a problem, break it into smaller parts, determine the risks, design appropriate controls, implement those controls, test them, and continuously improve them.

This makes the role strongly connected to engineering thinking: identify the problem, understand the requirements, design a solution, implement it, test it, and improve it.

### Asset Management and Asset Inventory

A security engineer cannot properly secure something they do not know exists. Organizations therefore need an accurate inventory of their digital assets. An asset inventory can contain information such as an asset's name, type, IP address, physical location, network position, applications running on it, access permissions, and ownership information. This gives the security team visibility into the environment and helps identify which systems require protection.

### Security Policies

Security policies define the organization's security expectations and rules. A security engineer can help create, implement, and maintain these policies based on established security principles.

An important lesson was that security policies cannot always be followed exactly because business requirements sometimes require exceptions. In these situations, the security engineer does not simply ignore the policy. Instead, they evaluate the situation, determine whether an exception is acceptable, and recommend mitigating controls to reduce the additional risk.

### Secure by Design

Security should not be added only after a system has already been built. A security engineer should incorporate security from the beginning through a **Secure by Design** philosophy.

This can involve secure network architecture, hardening Windows and Linux systems, securing Active Directory, and integrating security into the software development lifecycle.

### Security Assessment and Assurance

Security is not a one-time activity. Even if an organization initially designs and implements secure systems, new vulnerabilities, threats, technologies, configurations, and business changes can introduce new risks.

Security engineers therefore participate in activities such as security assessments, audits, red-team exercises, purple-team exercises, and remediation of identified findings. The purpose is continuous improvement of the organization's security posture.

### Humans and Security Awareness

One of the major lessons was that **humans are considered the weakest link in organizational security**. Even strong technical controls can be undermined by human mistakes, social engineering, phishing, poor security practices, or lack of awareness.

Security engineers may therefore help organize security awareness sessions and training so employees understand common attacks and security responsibilities.

### Compliance and Auditing

Security engineering also interacts with regulatory and organizational requirements. Depending on the organization and industry, security engineers may work with frameworks and standards such as PCI-DSS, HIPAA, SOC 2, ISO 27001, and NIST 800-53.

Audits help organizations identify non-compliance and security weaknesses, while security engineers can help address findings and maintain the organization's security requirements.

### Security Tooling

A security engineer may work directly with security technologies such as **SIEMs, firewalls, WAFs, and EDRs**. Depending on the organization, this can involve configuring tools, tuning detection rules, evaluating products, or helping management decide which security technologies are appropriate.

### Tabletop Exercises

A **tabletop exercise** is a theoretical exercise used to evaluate an organization's operational readiness during a security incident or crisis.

For example, an organization could simulate a phishing attack that compromises an employee endpoint. Different members of the security and IT teams then explain what they would do according to the organization's incident-response procedures and playbooks.

The organization can therefore practice its response without requiring a real attack.

### Disaster Recovery and Business Continuity

Security engineers may participate in disaster recovery, business continuity, and crisis-management planning. During a disaster or crisis, the priority of executive management is **business continuity** — keeping the organization's essential operations functioning.

This demonstrates an important security-engineering principle: security cannot be considered separately from the business. A theoretically perfect security system that prevents the organization from operating is not a useful business solution.

### Security and Business Requirements

Security engineering requires balancing **security with business objectives**.

A completely isolated and powered-off system might be extremely secure, but it cannot perform useful business operations. Therefore, security engineers must consider security, cost, usability, availability, implementation difficulty, operational requirements, and business objectives when making decisions.

The goal is not simply to make something as restrictive as possible. The goal is to achieve an appropriate level of security while allowing the organization to function.

## Key Takeaways

- A security engineer helps protect an organization's overall digital security posture.
- Security engineering is broader than penetration testing.
- An organization needs an accurate **asset inventory** to understand what it must protect.
- Security policies establish organizational security requirements.
- Business requirements can sometimes require **security policy exceptions**.
- Exceptions should be evaluated using security principles and accompanied by mitigating controls where appropriate.
- **Secure by Design** means considering security from the beginning rather than adding it only after deployment.
- Security requires continuous assessment and improvement.
- **Humans are considered the weakest link** in organizational security.
- Security awareness helps reduce human-related security risks.
- Security engineers may work with SIEM, firewall, WAF, and EDR technologies.
- **Tabletop exercises** test organizational readiness for security incidents.
- Disaster recovery and crisis management require planning before an incident occurs.
- During a disaster or crisis, executive management prioritizes **business continuity**.
- Security decisions must account for business objectives, cost, usability, availability, and operational requirements.
