## What I Learned

### Authentication

Authentication is the process of verifying that a user is who they claim to be.

A common authentication system uses:

- Username
- Password

The security of the authentication system depends heavily on how securely credentials are created, stored, and verified.

---

## Strong vs Weak Passwords

Weak passwords are easier for attackers to guess or recover.

Examples of weak password characteristics:

- Short passwords
- Common words
- Predictable patterns
- Reused passwords
- Easily guessable personal information

A stronger password should be:

- Long
- Difficult to guess
- Unique
- Not reused across multiple services

Password managers can help users generate and store strong unique passwords.

---

## Password Attacks

Attackers can attempt to obtain valid credentials through different techniques.

Common examples include:

- Brute force
- Credential stuffing
- Password spraying
- Password guessing

---

## Brute Force

A brute-force attack attempts many possible passwords until the correct password is found.

Simplified model:

    Username
       ↓
    Password 1 → Failed
       ↓
    Password 2 → Failed
       ↓
    Password 3 → Success

Weak passwords and unlimited login attempts make brute-force attacks more practical.

Defenses include:

- Strong passwords
- Rate limiting
- Account lockout
- MFA
- Monitoring and alerting

---

## Credential Stuffing

Credential stuffing uses previously leaked username/password combinations against another service.

The attack relies heavily on **password reuse**.

Example:

    Website A breached
          ↓
    Username + Password leaked
          ↓
    Attacker tries same credentials
          ↓
    Website B
          ↓
    Account compromise

Using unique passwords for different services reduces the impact of credential reuse.

---

## Password Spraying

Password spraying is different from traditional brute force.

Instead of trying many passwords against one account, an attacker tries one common password against many accounts.

Example:

    password123
       ↓
    user1 → Failed
    user2 → Failed
    user3 → Success
    user4 → Failed

This can help attackers avoid triggering account lockouts designed to detect repeated attempts against a single account.

---

## Password Hashing

Passwords should not normally be stored as plaintext.

Instead, applications can store password hashes.

Simplified model:

    Password
       ↓
    Hash function
       ↓
    Password hash

During authentication:

    Entered password
       ↓
    Hash
       ↓
    Compare with stored hash

A hash is designed to be one-way, meaning it should not simply be reversible back into the original password.

---

## Multi-Factor Authentication

MFA requires more than one authentication factor.

Common authentication factors include:

### Something You Know

Examples:

- Password
- PIN

### Something You Have

Examples:

- Phone
- Hardware security key
- Authentication device

### Something You Are

Examples:

- Fingerprint
- Face recognition

MFA improves security because compromising one factor does not necessarily give an attacker everything needed to authenticate.

---

## TOTP

TOTP stands for **Time-Based One-Time Password**.

It generates temporary codes that change over time.

A typical authentication flow is:

    Username + Password
           ↓
    Password accepted
           ↓
    TOTP code requested
           ↓
    Temporary code entered
           ↓
    Authentication completed

The temporary nature of the code makes it more difficult for a stolen password alone to provide persistent access.

---

## Authentication Security

Authentication security should not depend only on passwords.

A stronger authentication system can combine:

    Strong password
          +
    MFA
          +
    Rate limiting
          +
    Monitoring
          +
    Secure credential storage

---

## Password Managers

Password managers can help users:

- Generate strong passwords
- Store unique passwords
- Avoid password reuse
- Manage many credentials securely

This makes it easier to use a different strong password for every service.

---

## Authentication Attack Mental Model

When evaluating an authentication system, consider:

    How strong are the passwords?
            ↓
    Can passwords be guessed?
            ↓
    Can many attempts be made?
            ↓
    Are credentials reused?
            ↓
    Are passwords securely stored?
            ↓
    Is MFA enabled?
            ↓
    Are suspicious attempts detected?

## Key Takeaways

- Authentication verifies a user's identity.
- Weak passwords make authentication easier to attack.
- Brute force attempts many passwords against a target account.
- Credential stuffing uses previously leaked credentials against other services.
- Password spraying attempts a common password against many accounts.
- Passwords should be securely hashed rather than stored as plaintext.
- Password reuse increases the impact of credential leaks.
- MFA adds additional authentication factors beyond a password.
- TOTP provides temporary authentication codes.
- Authentication factors can be based on something you know, have, or are.
- Rate limiting and account protections can make automated password attacks harder.
- Strong unique passwords significantly reduce the effectiveness of credential-based attacks.
